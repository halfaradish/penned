# 账户可增可改可删 + 「添加账户」重做（含资产页列表）

## 诊断（已核对代码，非猜测）

| 问题 | 根因 |
|---|---|
| 账户删不掉 | 全仓**没有任何按账户删除的 DAO 或入口**。`AccountDao`（`data/db/dao/BookDao.kt:41-75`）只有 `softDeleteByBook`（删账本时级联用）；资产页行无 clickable、无长按、无滑动（`ui/assets/AssetsScreen.kt:257-286`） |
| 无法自定义 | 弹窗只在 8 个固定预设里选（`AssetsScreen.kt:137-150`），没有一木那种每组末尾的「自定义」格；名称字段标签写着「显示：储蓄卡」，看起来像不可改 |
| 界面丑 | `AlertDialog` + 8 个竖排文字 chip + 两个白框 `OutlinedTextField`（`AssetsScreen.kt:340-401`），一行一个控件、没有版面结构 |
| 顺带的两个真 bug | ①列表头部永远显示「默认分组」（`groupName` 从未写入，`AssetsScreen.kt:242-256`）；②行副标题显示枚举名，导致「支付宝」那行写着"储蓄卡"（`AssetsScreen.kt:126-132` 被 `:270` 用） |

好消息：`AccountEntity` 早有 `deleted/updatedAt`（D003），**加删除不需要 DB 迁移、不动 schema JSON**；`AccountType` 按名字存字符串，本次也不动枚举。

## 一、数据与业务层（零 schema 变更）

1. `AccountDao` 补两个方法（与 `TransactionDao.restoreAll:134` 同形）：
   - `softDelete(id, now)` → `UPDATE accounts SET deleted = 1, updatedAt = :now WHERE id = :id`
   - `restoreAll(ids, now)` → 撤销用
2. `TransactionDao` 补 `countByAccount(id): Int` → `deleted = 0 AND (accountId = :id OR targetAccountId = :id)`
3. `AssetsViewModel`：
   - `deleteAccount(account)`：有流水 → 发提示不删；无流水 → 软删 + 记 `deletedIds`
   - `undoDelete()/clearUndo()` 与 `HomeViewModel:130-150` 同形；`message` 流 + `consumeMessage()`

**删除语义（你选定）**：有流水的账户禁止删除并提示「「现金」还有 3 笔流水，先处理流水再删除」；空账户可删，10 秒内可撤销。数据不会丢，净资产也不会凭空对不上。

## 二、新增/编辑账户页（新文件 `ui/assets/AccountEditScreen.kt`，独立页面）

从 FAB 滑入的完整页面（与「记一笔」同一范式），拆成有状态 `AccountEditScreen` + 无状态 `AccountEditContent`（照 `AssetsContent` 既有拆法，便于截图测试）：

```
← 添加账户 / 编辑账户
─────────────────────────────
类型
 [ 资金 ][ 信贷 ][ 理财 ][ 负债 ]   ← PennedSegmentedTabs
 ⬤现金  ⬤储蓄卡 ⬤支付宝  ⬤微信钱包   ← 4 列图标网格（56dp 头像 + 12sp 名称）
 ⬤自定义                            ← 每组最后一格，Plus 图标
─────────────────────────────
详情
┌───────────────────────────┐
│ 名称          现金         │   ← 行式输入，值右对齐，不用白框 OutlinedTextField
│ ───────────────────────   │
│ 初始余额          0.00  元 │   ← tnum 等宽
└───────────────────────────┘
[         保存账户         ]      ← 底部常驻（imePadding）
（编辑模式底部多一个朱砂「删除账户」）
```

- 选中态 = 主色实心圆 + 勾 + 名称转 `primaryInk`；点「自定义」→ 清空并聚焦名称输入，类型取该组代表类型（资金→DEBIT / 信贷→CREDIT / 理财→INVEST / 负债→DEBT）
- 沿用既有语义：选预设只设类型 + 预填默认名，**不覆盖用户已输入的名称**（board 待办第 16 行的修复不能回退）
- 路由 `account?editId={editId}`（照 `PennedApp.kt:146-156` 的 `add?editId=` 写法）；`composable("assets")` 注入 `onAddAccount/onOpenAccount`
- 新 `AccountEditViewModel`：`load(id)` 预填、`save(...)` 用 `upsert(entity.copy(...))`（保留 id/createdAt/deviceId）、`delete(id)` 复用第一节的语义
- 旧的 `AddAccountDialog` 整个删掉（不留死代码）

**承载形式选独立页面**的原因：排版空间足、键盘不挤压、并且能正常做 Robolectric 截图测试——弹窗/抽屉里带文本输入是本仓已知的截图盲区（`board.md:17`，旧弹窗至今只能做存在性断言）。
