## 二、交付口径（所有切片共同遵守）

1. **一次迁移建表**：v8→v9 建 `keyword_rules` 与 `pending_entries` 两表（都带同步字段），后续切片不再升版本；`9.json` 入库 + `MIGRATION_8_9` + migration 测试。
2. **零新增依赖**（本规格最大的硬约束，比 M3 的"不新增"更硬——M4 原本最可能要引 OCR/序列化）：
   - 网络走既有 **OkHttp**（D058）；JSON 走平台 **`org.json`**（D058 先例：`UpdateManifest` 即此写法，不引序列化库）
   - 图片解码 / 缩放 / 压缩走平台 `BitmapFactory` / `Bitmap.compress`（不引 Coil 等图像库）
   - 相册走 `PickVisualMedia`（minSdk 26 自动回退到 SAF，**不需要读存储权限**）；拍照走系统相机 `MediaStore.ACTION_IMAGE_CAPTURE`（**不申请 CAMERA**）；分享收图走 `ACTION_SEND` + `image/*` intent-filter
   - → `gradle/libs.versions.toml` 一个字都不动；验收含"零新依赖"核对
3. **不引 WorkManager / AlarmManager / 前台服务 / 定时任务**（M3 §六 延续）。M4 唯一的后台形态 = `NotificationListenerService`（系统按需绑定、可随时在系统设置里撤销授权）；**不读短信、不装无障碍**。
4. **LLM 三原则**：
   - **BYOK**：用户自带 Key，应用不含任何服务端、不代理、不留存调用记录
   - **显式开关 + 显式触发**：AI 默认关；每张图、每句话调不调由用户点，绝不后台预跑
   - **分类与账户永远本地映射**：LLM 只许回 收支类型 / 金额 / 商户 / 时间 / 备注，**不许回分类或账户 ID**（防幻觉的唯一有效手段）
5. **三条管道共用一套底座**：`KeywordRules`（关键词 → 分类/标签，纯函数匹配）、`LlmClient`（文本与图像两用，同一份出参 schema）、`识别结果 → 草稿` 的映射。**机器只填草稿，入账必须过用户确认**。
6. **`pending_entries` = 非交互管道（截图 / 通知）的统一候选池**：识别成功才落库、失败不落（当场报错可重试）；入账 = 打开记一笔页（预填 + 对应 `source`），保存成功把候选标 `ACCEPTED` 并回填 `txId`；用户放弃则留在列表（可再记或丢弃）。**杀进程不丢**（这是它落库的唯一理由）。
7. **解析 / 匹配一律 domain 纯函数 + 表驱动单测**；通知文案样本用**脱敏 fixture 进仓库**（微信 / 支付宝各 ≥6 条），不得引用 `docs/local/` 的真实账单。
8. 新页面先补 `docs/界面规范.md` 逐屏版式（**从 §13·补二十九 起编号**），交付含 Roborazzi 浅/深基线 + `@Preview` 可渲染；隐私文案（"这张图将发给 X"、"Key 只存本机"、"原文不进 AI"）收敛到一处常量，不各页各写。
9. 模拟机走查照 M3 §二·7（`GxuDev` 只读/探针 或 `PennedM2`），走查前后核对库内"活跃 / 软删"条数；**通知监听用 `adb shell cmd notification post` 造通知验证**（不必依赖真实微信/支付宝）。
10. **开工顺序：6 片分 2 批、每批 3 片**（照 M3 §二·8）：批次一 = 底座（M4-0 / M4-1 / M4-2），批次二 = 三条管道（M4-3 / M4-4 / M4-5）。批次内可换序，批次间串行；某片偏大可拆成两次会话（M3-4 先例）。

## 三、切片

### 批次一 · 底座（P0，先做）

#### M4-0 schema 地基 + 智能设置项（v8→v9 一次迁移，无 UI）

- 新表 **`keyword_rules`**（关键词规则，与分类/标签同账本域——两者的目标都是账本内实体）：
  `id / bookId / keyword / targetType(CATEGORY|TAG) / targetId / priority / enabled / createdAt / updatedAt / deleted / deviceId`；索引 `bookId`。
  口径：匹配 = 按 `priority` 升序取**第一条命中**（同优先级按 `createdAt`）；`enabled = false` 跳过；**空关键词拒绝入库**；匹配时去首尾空白、大小写不敏感（中文无大小写，英文商户名用得上）。
- 新表 **`pending_entries`**（机器识别候选池）：
  `id / kind(SCREENSHOT|NOTIFICATION) / sourceApp? / rawText? / type(EXPENSE|INCOME|TRANSFER|UNKNOWN) / amountCents? / occurredAtEpochMinute? / merchant? / note? / categoryId? / status(PENDING|ACCEPTED|DISCARDED) / txId? / createdAt / updatedAt / deleted / deviceId`；索引 `status`。
  口径：`amountCents` 与 `occurredAtEpochMinute` **可空**（解析不出就是空，**不猜**）；**没有"解析失败"状态**——失败不落库。
- DAO：`KeywordRuleDao`（按账本观察 / upsert / 软删 / 上下移 / 启停）、`PendingEntryDao`（插入 / 按状态观察 / 标记 `ACCEPTED` + 回填 `txId` / 丢弃 / 清空）。
- 纯函数：`KeywordRules.match(text, rules): RuleHit?` —— 表驱动（优先级 / 多命中取先 / 禁用跳过 / 大小写 / 空关键词 / 二级分类与标签目标）。
- 设置项（`SettingsRepository` 同款 DataStore 键）：`llm_enabled`（默认 **false**）、`llm_base_url`、`llm_api_key`、`llm_model`、`llm_vision_model`（空 = 跟 `llm_model`）、`auto_entry_enabled`（默认 **false**）、`auto_entry_packages`（逗号串，默认空 = 什么都不处理）。
- 验收：`9.json` 入库；`MIGRATION_8_9` + migration 测试（建 v8 库塞旧数据 → 迁移 → 断言两新表与索引存在、旧数据零变化）；匹配纯函数表驱动 ≥10 例；设置读写测试；`./gradlew build test lint` 全绿。

#### M4-1 分类关键词规则（引擎 + 页面 + 记账接入）

- 页面：我的 → **智能** 分组 → 「分类关键词」——列表行 = 关键词 + 「→ 分类名 / 标签名」+ 启用开关 + 右滑删除；行尾 ↑↓ 调优先级（照既有手动排序做法）；「新增规则」底部抽屉（关键词输入 + 目标二选一（分类 / 标签）+ 目标选择器，复用分类树抽屉与标签选择器）。
- 引擎接入三处（全部"**建议值、可改**"，不静默决定）：
  ① 一句话解析（M4-3）→ 命中就填分类（或标签）
  ② 截图识别结果映射（M4-4）→ 商户名 / 备注命中就填分类
  ③ 通知解析（M4-5）→ 命中就填分类
- **不接入**记一笔页的实时输入联想（打字时分类乱跳，代价大于收益）——进提案区。
- 明确不做：规则导入导出、正则语法（只做"包含"匹配）、规则热更新 / 云规则包、"自学习"分类器。
- 验收：`KeywordRuleDaoTest`（软删 / 排序 / 启停）；匹配 → 分类的映射测试（一句话与截图各一条）；截图浅/深（规则列表 / 新增抽屉）；模拟机走查（建 `肯打鸡 → 食品餐饮` → 一句话"肯打鸡花了15" 自动带出分类）。

#### M4-2 BYOK：AI 设置页 + `LlmClient`

- 设置页（我的 → 智能 → 「AI 设置」）：总开关（默认关）+ `服务地址`（示例提示，如 `https://open.bigmodel.cn/api/paas/v4`）+ `API Key`（密文框 + 显示/隐藏）+ `模型` + `视觉模型`（可空）+ 「测试连接」+ 「清除 Key」；页脚隐私说明（Key 只存本机 DataStore 明文；调用直连你填的地址；不做任何上报；不填不联网）。
- `LlmClient`（`data/llm/LlmClient.kt`；构造注入 `OkHttpClient` 与配置快照，**网络层可替换**以便假服务器测试）：
  - 调用形态：OpenAI 兼容 `POST {base}/chat/completions` + `Authorization: Bearer`；文本 = 一条 user 消息；图像 = 一条 user 消息含 `image_url`（`data:image/jpeg;base64,…`）
  - 出参：prompt 约束严格 JSON + **本地强校验**；解析只认 `choices[0].message.content` → JSON，模型回的闲聊/多余字段一律丢弃
  - 出参 schema（文本与图像共用；缺金额即判失败）：
    `{"type":"EXPENSE|INCOME","amount":12.34,"merchant":"肯德基","time":"2026-10-17 12:30","note":"…"}`
    金额按**元**收（数字或字符串），落库前经 `Money` 换 Long 分；时间解析失败取"现在/今天"
  - 超时：连接 10s / 读 60s（图像调用慢）；协程可取消
  - 错误分类（UI 各自给文案）：未配置 Key / 网络不可达 / 401（Key 无效）/ 403 / 429（限流）/ 超时 / 非 JSON / JSON 但字段不符
  - **不做**：流式、自动重试重发（重试 = 用户点）、多轮对话、函数调用、Key 加密存储（无依赖可用，页面明示风险）
- 验收：`LlmClientTest`（假服务器照 M2 `FakeHttpServer` 先例：200 正常 / 401 / 超时 / 非 JSON / JSON 缺字段）；设置页读写与「未配置」分支；截图浅/深（设置页 / 测试连接三态）。

### 批次二 · 三条管道（P1）

#### M4-3 一句话记账

- 入口：①首页悬浮记账入口**长按**弹「一句话记账 / 截图导入」两个快捷入口（单击维持记一笔，FAB 的 368↔56dp 形变几何与既有测试**不动**）②我的 → 智能 → 「一句话记账」。
- 页面：多行文本框（自动聚焦）+ 「粘贴」（读剪贴板）+「解析」→ **解析结果卡** →「保存」。
  - 结果卡五行：类型（支出/收入）/ 金额 / 分类 / 日期 / 备注，**每行可点改**（分类走既有分类抽屉、日期走既有日期选择、金额走既有金额键盘）；分类若来自关键词规则，行上给「来自关键词规则」小标记
  - 保存：`source = TEXT`；账户留空（无账户记账是既有合法口径）；保存后首页提示条「已记账」+「撤销」（照既有范式）
- 本地解析器（`domain/QuickParse.kt`，纯函数 + 表驱动）：
  - 金额：阿拉伯数字（容许千分位 / 小数点 / 全角数字 / `元` / `块`）；**取最后一个金额候选**，紧跟量词（个/张/杯/碗/件/只/包…）的整数不算金额（`买了2个包子花了10` → 10）；**没有金额 = 解析失败**，提示"没找到金额"
  - 类型：`收到 / 工资 / 报销 / 退款 / 利息 / 红包` → 收入，其余默认支出
  - 日期词：`今天 / 昨天 / 前天 / 大前天 / 上周X / 周X / 星期X / 本月X日 / M月D日 / N天前`，换算复用 `AddDate`；缺省 = 今天
  - 备注 = 剔掉日期词与金额后的剩余文本（去首尾空白、压多余空格）
  - 分类：交给关键词规则；**没命中就留空**（不猜）
- LLM 兜底：**只在用户点「AI 解析」时调**（不自动调、不花用户的钱）；未配置或缺 Key 时按钮给出引导（跳 AI 设置）；LLM 结果同样过本地校验与关键词规则映射，且**不覆盖用户在结果卡上改过的行**（改动过的行打脏标记）。
- 明确不做：语音 ASR；一句话拆多笔（"早饭 10 午饭 20" → 提案区）；金额/类别的模糊估算。
- 验收：解析器表驱动 ≥12 例（`肯打鸡花了15` / `昨天打车 32.5` / `上周三工资 8000` / `10月1日 收到红包 200` / 千分位 / 全角数字 / 无金额 / 多金额取末 / 只有日期 / 只有备注 / 量词干扰）；假服务器跑通「AI 解析」；Compose（输入 → 解析 → 改分类 → 保存 → 首页可见且记录方式为"一句话记账"）；截图浅/深（输入态 / 结果卡 / 失败态）。

#### M4-4 截图导入

- 入口：①首页 FAB 长按 →「截图导入」②我的 → 智能 → 「截图导入」③**系统分享菜单**（`ACTION_SEND` + `image/*`；`MainActivity` 收 `EXTRA_STREAM` 后跳转，注意单 Activity 的 `onNewIntent`）④页内：相册选图（`PickVisualMedia`，可多选）/ 拍照（系统相机）。
- 流程：选图 → 解码 + 压缩（**长边 1280 / JPEG 85**）→ 调视觉模型（BYOK）→ 严格 JSON → 本地校验 → **落 `pending_entries`（kind=SCREENSHOT）** → 直接打开记一笔页预填（`source = SCREENSHOT`；备注沿用识别出的商户/说明）→ 保存成功把候选标 `ACCEPTED` 并回填 `txId`。
  - 多选 = 逐张**顺序**识别（不并发，省流量、避限流），每张落一条候选；识别完打开第一条的记一笔页，其余留在「待确认」页
  - 失败（未配置 Key / 网络不可达 / 限流 / 解析不出金额 / 模型说"这不是账单"）：页内报错卡 +「重试」+「去 AI 设置」，**不落库**
  - 出图前页面明示："这张图将发送给 {域名} / {模型}"
  - 识别完即丢原图（只用 `cacheDir` 临时文件，不留存）
- 明确不做：**本地 OCR**（§五·1 已裁决）、多张并发识别、一张图拆多笔（图里有多笔时**只取主笔**并提示"这张图里还有别的内容，暂不支持"）、保存原图。
- 验收：`LlmDraft` 映射表驱动（正常 / 缺金额 / 金额带"元"字 / 时间为空 / 类型缺省 / 脏字段 / 非账单）；假服务器端到端（PNG fixture → 预填）；截图浅/深（入口页 / 识别中 / 失败卡 / 预填后的记一笔页）；模拟机真图 ≥6 张（微信支付成功 / 支付宝支付成功 / 支付宝转账 / 银行 App 截图 / 美团订单 / 一张非账单图应给"没看出这是账单"）——真图放 `docs/local/` 不入库。

#### M4-5 自动记账（通知监听 + 待确认）

- 权限与服务：
  - Manifest：新增 `<service>`（`android:permission="android.permission.BIND_NOTIFICATION_LISTENER_SERVICE"` + intent-filter `android.service.notification.NotificationListenerService` + `android:label`，在系统"通知使用权"列表里显示的名单）+ 权限 `POST_NOTIFICATIONS`（33+ 运行时申请，**只用于候选提醒**）
  - 授权引导：我的 → 智能 → 「自动记账」页 = 状态卡（已授权 / 未授权 +「去开启」跳 `Settings.ACTION_NOTIFICATION_LISTENER_SETTINGS`）+ 总开关（默认关）+ **App 白名单**（勾选，默认空 —— 不勾任何 App 就什么都不处理）+「N 条待确认」入口 + 隐私说明（原文只在本机、**不进 LLM**、不读短信、不装无障碍、可一键清空）
- 解析（`domain/NotifyParse.kt` 纯函数 + 表驱动；**规则 = 代码内常量表**，per App 一组正则，不落库、不热更新——热更新进提案区）：
  - 起步覆盖微信 / 支付宝：特征词（`到账 / 收款 / 付款成功 / 扣款 / 转账`）+ 金额正则 `¥?([\d,]+\.\d{2})` + 方向判定
  - **解析不出金额或方向 → 丢弃**（宁可漏，不可错记）；命中的关键词规则把分类带进候选
- 落库与提醒：命中 → 写 `pending_entries`（kind=NOTIFICATION、`sourceApp` = 包名、`rawText` = 通知正文）→ 发一条本 App 通知（渠道 `auto_entry`，"识别到一笔 12.50 的支出，点这里确认"）→ 点击进「待确认」页。
  - **去重口径**：`NotificationListenerService` 会重复回调同一条通知 —— 插入前按 `(sourceApp + 同分钟 + rawText)` 查重，重复直接跳过（写测试钉住）
- 「待确认」页（入口 = 自动记账页 / 通知点击）：列表行 = 来源 App + 金额 + 方向 + 时间 + 原文一行（`maxLines = 1`、`onSurfaceVariant`）+ 右滑「丢弃」；点行 = 打开记一笔页预填（`source = AUTO`）；顶部「全部丢弃」；空态给"去开自动记账"的出路。**页脚一处「清空已处理」**（把 `ACCEPTED/DISCARDED` 的行删掉）。
- 明确不做：通知栏「一键入账」按钮（§五·2 已裁决：误记风险）、白名单外 App 的解析（提示"暂不支持"而非硬猜）、短信 / 无障碍读屏、历史通知回扫（只处理服务启用后新到的）。
- 验收：通知文案解析表驱动（微信 ≥6 条：付款成功 / 收款到账 / 转账 / 红包退回 / 零钱提现 / 群收款；支付宝 ≥6 条：付款成功 / 收款到账 / 花呗扣款 / 转账 / 余额宝收益 / 退款；**全部为脱敏 fixture**）；去重测试；候选 → 入账 → `ACCEPTED` 回写测试；Compose（白名单 / 待确认列表 / 丢弃 / 空态）；截图浅/深；模拟机用 `adb shell cmd notification post -S bigtext -t '微信支付' …` 造 3 条通知 → 待确认 3 条 → 入账 1 条 → 首页该行记录方式显示"自动记账"。
