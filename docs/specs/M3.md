# 规格 M3：会员功能解锁（冻结 v1.0，2026-10-12 · §五 7 条裁决已并入）

来源：`docs/可行性分析与技术方案.md` §三（功能拆解）与 §十 里程碑表 M3 行（"多账本、周期、模板、标签、愿望清单、组合筛选、资产/分期/年费、主题、自定义统计、数据小卡片"）；`docs/一木记账权益.md`（"数量限制类"权益清单）；`docs/信息架构分析.md` §二·5（我的页宫格）/ §三（数据模型补充）；`docs/local/一木模拟机探索/探索报告.md`（记一笔四 Tab、周期记账预生成与 1999 上限、小票/精准导出）；M0 不做清单（周期/模板/愿望清单、债务/分期/理财快照表 → M3）；M1 收官遗留（D057：退款交互留 M3）；看板待办（D026：账户停用/归档与流水迁移留 M3 资产模块）。

定位：把权益表里**数量限制类 + 本地可算类**的会员功能一次做完——这些功能没有一项需要服务端，全部本地免费。方案 §三 B 的工程含义照办：**数据结构一开始就按"无限量"设计，不写任何限制代码**（没有"免费 1 个 / 会员 3 个"的分支，也没有升级引导）。

前置（已完成，不重复做）：M1 多账本 / 分类预算 / 账本隔离 / 账本管理页 / 分类管理 / 密码锁 / 导入导出；M2 应用内更新通道（此后每个版本走 `git tag` 自动发包，D067）。

继承口径（违反 = 返工）：金额一律 Long 分（D001）、余额与统计一律重算不落库（D004）、退款/优惠/报销是**流水属性**而非独立流水（D007/D008）、全表 uuid + createdAt/updatedAt/软删 + deviceId（D003）、schema 变更必须 v+1 + Migration + schema JSON 入库 + migration 测试（AGENTS）、依赖不得新增（AGENTS）、界面走 `docs/界面规范.md`（D043/D044）。

## 二、交付口径（所有切片共同遵守）

1. **一次迁移建表**：M3 需要的表/列在 **M3-0** 一次迁移到位（v5→v6，含 `debts`——§五·1 已裁决实体式，债务不再单独迁移）；后续切片只写 DAO/UI/测试，不再逐片升版本。**例外两处**：分类隐藏的 `categories.hidden` 随 M3-1 迁移（v6→v7，**勘误**：草案以为它是 v1 预留字段，实际 1~6.json 都没有，只能真加一列，D074）；愿望清单 `wishlist_items` 随 M3-15 迁移（v7→v8）。
2. 一个切片 = 一个会话 = 独立提交；`./gradlew build test lint` 全绿才算完成（AGENTS DoD）。
3. 涉及钱 / 日期 / 口径的纯函数（净额、债务余额、期次推进、年费到期、房贷计算、盈亏）一律**表驱动单测**；口径写在 domain 层，UI 不许自己算。
4. 新页面先补 `docs/界面规范.md` 逐屏版式（从 §13·补十二 起编号），再写代码；交付含 Roborazzi 浅/深基线 + `@Preview` 可渲染。
5. 不新增依赖；**不引 WorkManager / AlarmManager / 后台服务**（§六）。
6. 新增表一律带同步字段（uuid 主键 + createdAt/updatedAt + deleted + deviceId），查询一律过滤 `deleted = 0`；多对多一律独立关系表（照 `transaction_tags`）。
7. 模拟机走查：`GxuDev`（用户真实数据，**只读或自建探针**，走查前后核对"活跃/软删"条数）或 `PennedM2`（干净 release 机）；测试产物截图归档 `docs/local/界面重构验证/`。
8. **开工顺序（§五·7 裁决）**：分批次推进，**默认 3 片一批**（本规格 M3-0~M3-17 共 18 片 = 6 批）；批次内各片互不依赖、可换序；某片明显偏大（如 M3-4 债务）可单片独立成批，依赖更紧的两片也可合并成一批——批次边界按依赖与体量灵活调整，**但批次内的片必须先全部交付再进下一批**。

## 三、切片

### 批次一 · 把一笔账记全（P0，先做）

#### M3-0 schema 地基（v5→v6，一次迁移，无 UI）

- 新表：
  - `tx_templates`（模板）：`id/bookId/name/type/amountCents/categoryId?/accountId?/targetAccountId?/note?/feeCents/sortOrder/sync 字段`
  - `template_tags`（模板-标签多对多）：`templateId/tagId`（主键）
  - `recurring_rules`（周期规则）：`id/bookId/name/type/amountCents/categoryId?/accountId?/targetAccountId?/note?/feeCents/periodType(DAILY|WEEKLY|MONTHLY|YEARLY)/interval/startEpochDay/nextEpochDay/endEpochDay?/enabled/lastGeneratedAt/sync 字段`
  - `bill_filters`（账单组合）：`id/bookId/name/sortOrder` + 条件列（多值条件存逗号分隔 TEXT：`categoryIds/accountIds/tagIds`，配套纯函数编解码）
  - `asset_snapshots`（理财快照）：`id/accountId/dateEpochDay/valueCents/note?/sync 字段`
  - `debts`（债务；§五·1 裁决实体式，随本片一次建好，**M3-4 不再迁移**）：`id/bookId/direction(BORROW|LEND)/counterparty/principalCents/startEpochDay/dueEpochDay?/note?/closed/sortOrder/sync 字段`
- 新列：`transactions.reimburseCents INTEGER NOT NULL DEFAULT 0`、`transactions.recurringRuleId TEXT`（可空）、`transactions.debtId TEXT`（可空）、`accounts.annualFeeCents INTEGER NOT NULL DEFAULT 0`、`accounts.feeMonth INTEGER`（1~12，可空）、`accounts.feeDay INTEGER`（1~31，可空）、`accounts.lastFeePaidYear INTEGER`（可空）
- 不动：`tags` / `transaction_tags`（v1 就有）、`accounts.archived`、`accounts.groupName`（v1 就有）、`categories.hidden`（**勘误**：它并不存在，由 M3-1 的 `MIGRATION_6_7` 新增，D074）
- 验收：`6.json` 入库；`MIGRATION_5_6` + migration 测试（建 v5 库塞旧数据 → 迁移 → 断言新表/新列存在、旧数据零变化）；`./gradlew build test lint` 全绿

#### M3-1 标签（二级标签 + 分类隐藏；`categories.hidden` 由本片新增列，`MIGRATION_6_7`）

- 数据：新增 `TagDao`——按账本观察两级标签、upsert、软删（连带 `transaction_tags`）、`tagsForTx(txId)`、`setTagsForTx(txId, ids)`（全量替换，单事务）、按标签查流水（给 M3-7 用）
- 记账：记一笔信息条新增「标签」chip → `PennedSheet` 抽屉（Robolectric 可 idle，见看板已知坑）：一级标签 chip + 展开二级 + 「＋ 新建」（输入名即建即选）；多选；信息条回显「标签 · N」
- 展示：详情页新增「标签」行（多个用 `·` 连接）；编辑页回填；首页行**不显示标签**（保持列表克制）
- 管理：我的 → 标签管理页——两级列表 + 新增（一级/二级）+ 重命名 + 删除（软删，提示「已用于 N 笔流水」，删一级时连它的二级一起软删并摘掉流水关联）+ **隐藏**开关（`hidden = true`：记账选择器与筛选中不出现，已记账的流水仍照常显示；**隐藏一级标签连它的二级一起收起**——父 chip 不画了、二级就没有入口，与分类隐藏同一口径）
- **分类隐藏（随本片给 `categories` 加 `hidden` 列，D074）**：分类管理页加同款「隐藏」开关（口径与标签一致：不出现在记账宫格与筛选、已记账流水照常显示）——隐藏的一级分类连它的子树一起收起来；文案与行为的不一致（旧看板条）核对后**已经一致**（副标题写的是"删除"，不再有"写隐藏实际软删"的问题），本片只加能力
- 验收：`TagDaoTest`（两级/软删/关系表替换/幂等）；`AddTagFlowTest`（选标签 → 保存 → 详情页可见 → 编辑回填）；分类隐藏的宫格/筛选过滤测试；截图浅/深（记账抽屉 / 标签管理 / 详情标签行）；模拟机走查

#### M3-2 退款 / 优惠录入（无 schema 变更）

- 现状口径：`amountCents` 参与余额与统计，`refundCents` / `discountCents` 只作展示（M1 的只读实现即如此，**不改**重算口径，导入的历史数据保持自洽）
- 交互：记一笔（支出/收入）信息条新增「退款」（点开输入金额，复用金额键盘）与「优惠」；两者都填时行内显示「实付 = 金额 − 退款 − 优惠」
- **落库口径（§五·2 裁决 = 保存净额）**：保存时 `amountCents` = 用户输入金额 − 退款 − 优惠（净额），`refundCents`/`discountCents` 存各自原值；编辑时反推原价 = `amount + refund + discount`，往返幂等（表驱动断言）
- 校验：退款 + 优惠 > 金额时不拦，净额可为 0（照一木：全额退款 → 金额 0 + 退款额 > 0，详情页显示「已全额退款」标记，现有逻辑不变）
- 详情页：「退款」「优惠」两行改为可点（跳编辑页）；`RefundBadge` 文案沿用
- 验收：净额/反推纯函数表驱动（部分退款/全额/优惠/两者叠加/0）；截图（记一笔填退款态 / 详情全额退款）；模拟机：给一条探针流水填退款 → 余额与统计按净额变化、撤销复原
- **实现注（2026-10-12 交付时补，D075）**：「复用金额键盘」= chip 把同一个键盘指过去（`AmountField` 三格 + 提示条），不是二次弹窗；「实付」行改为**填了退款或优惠就显示**（只填一个是最常见形态）；退款 + 优惠 > 原价时净额夹 0 不拦；净额为 0 的行金额不写 "-0.00"，改由行上「退款 / 全额退款 / 优惠」标记说明（看板遗留随本片结清）

### 批次二 · 记全剩下三种（P0）

#### M3-3 报销录入

- 数据：启用 M3-0 的 `transactions.reimburseCents`；口径 = **报销金额缺省 0 表示按流水净额全额报销**
- 资产页报销卡口径（改 `TransactionDao.observeReimburseSums`）：
  - 可报 = `SUM(PENDING)` 下 `CASE WHEN reimburseCents > 0 THEN reimburseCents ELSE amountCents END`
  - 已报 = `SUM(DONE)` 同上；SQL 口径改动要补 DAO 测试
- 记账：记一笔的「不报销」chip（现为只读禁用样式）改为可点 → 抽屉：`不报销 / 待报销 / 已报销` 三选 + 「报销账户」选择（收到报销款的账户，可空）
- 编辑：已记账的流水在编辑页可改报销状态与金额；详情页「报销」行展示 状态 + 金额 + 账户（只读）；资产页报销卡随之重算
- 明确不做：报销单据/明细（一木导出有"报销明细"列但真实样本全空）、报销到期提醒
- 验收：`ReimburseMathTest`（默认全额 / 部分 / 已报口径）；DAO 测试（三种状态 + reimburseCents 边界 0/部分/超额）；截图（记一笔报销抽屉 / 详情报销行）；模拟机走查（可报/已报数字随状态变化）

#### M3-4 债务（§五·1 裁决 = 实体式；本批次最大一片，可按"数据+列表"与"记账 Tab+详情"拆两次会话）

- 数据：`debts` 表 + `transactions.debtId`（均已在 M3-0 的 v6 建好，**本片无迁移**）
- 余额口径（domain 纯函数，不落库，D004）：每笔债务的「剩余」= 本金 − 已归还；资产页债务卡 = 应付（BORROW 未结清合计）/ 应收（LEND 未结清合计）接真数据
- 净资产口径：`净资产 = Σ账户余额 − 应付 + 应收`（把债务并入资产页 NetAssetCard 的现有公式，纯函数 + 表驱动）
- 记账（照一木记一笔第四 Tab）：类型 Tab 加「债务」→ 选择债务 + 资金账户 + 金额 + 日期（借入：钱进资金账户、欠款增加；归还：反向）；生成的资金流水带 `debtId` 且 **`excludeFromStats = true`**（借入不是收入、还款不是支出——默认置上，详情页可改）
- 页面：资产页债务卡 → 债务列表页（应付/应收两段，卡片 = 对方 + 本金 + 已还/剩余 + 到期日 + 结清标记）→ 新建/编辑债务页 + 债务详情（还款记录列表 + 「记一笔还款」跳记一笔预填）
- 允许**负债类账户初始余额为负数**（看板提案：信贷/负债存量欠款；记账余额输入框放开负号，只对 `AccountType.DEBT`/`CREDIT`）
- 验收：债务余额/净资产纯函数表驱动（借入/部分归还/结清/两面）；DAO 测试；`excludeFromStats` 回归（借入后统计的收支不变）；截图（债务列表 / 新建债务 / 债务 Tab）；模拟机走查（借入 1000 → 现金 +1000、净资产不变；归还 400 → 应付 600）

#### M3-5 模板记账

- 数据：`tx_templates` + `template_tags`（M3-0 已建）；`TemplateDao`（列表/upsert/软删/重排）
- 页面：我的 → 模板记账——列表行 = 名称 + 摘要（类型 · 金额 · 分类/账户）+ 右滑删除；「新建模板」= 独立页面（复用记一笔的表单组件，字段：名称/类型/金额/分类/账户（转账两端）/备注/标签）
- 用模板：点模板行 → 进记一笔页**预填**（不直接入库，用户在记账页确认后保存）；记一笔页信息条加「模板」chip 打开同一个模板抽屉（等价入口）
- 快捷：保存成功后提示条给「存为模板」动作（10s，与撤销同范式）
- 明确不做：模板自动记账（那是周期记账）、模板排序拖拽（先按 sortOrder 手动上下移）
- 验收：`TemplateDaoTest`；预填纯函数测试（模板 → AddUiState 映射，含转账/标签）；`AddTemplateFlowTest`（选模板 → 预填 → 保存入库）；截图浅/深；模拟机走查

### 批次三 · 时间与找账（P0/P1）

#### M3-6 周期记账

- 数据：`recurring_rules`（M3-0 已建）+ `transactions.recurringRuleId`；`RecurringDao`
- 期次推进（domain 纯函数，表驱动）：日/周/月/年的下一期；**月对齐规则**：起始日为 29/30/31 时，短月取当月最后一天（1/31 → 2/28，闰年 2/29），后续期回到 31 日
- **生成策略（§五·3 裁决 = 打开即补）**：App 启动（`PennedApp` 层，与启动自动检查同处）时把已到期未生成的期数补生成（带 `recurringRuleId`），首页给一条可关闭的提示「周期记账已补记 N 笔」；不引后台任务、不产生未来日期的流水（预生成方案已否，见 §六）
- 幂等：同一规则同一期只用一条流水（`recurringRuleId` + 期序号去重；期序号可由 `dateEpochMinute` 推导）
- 页面：我的 → 周期记账——列表行 = 名称 + 摘要 + 「下次 M月D日」+ 启停开关；新建/编辑页（类型/金额/分类/账户/备注/周期/起止）；删除规则 = 软删规则，**已生成的流水保留**（提示条写明）
- 明确不做：后台定时生成、到期通知推送、规则变量金额、预生成未来流水（一木的 1999 条上限策略不采用）
- 验收：期次推进表驱动（跨月/跨年/闰年/月末对齐）；生成幂等与补记数量测试；`RecurringDaoTest`；截图；模拟机走查（建一条"每天"规则 → 启动补记 → 首页可见 → 再启动不重复）

#### M3-7 组合筛选 + 精准导出

- 范围：搜索页升级为**筛选页**——关键词（备注/分类名/金额，现有）+ 类型（支出/收入/转账/全部）+ 日期范围（复用 `AddDate` 换算）+ 账户（多选）+ 分类（多选，含二级）+ 标签（多选，M3-1 后）+ 金额区间 + 开关（不计入收支 / 不计入预算 / 结果含转账）

- 验收：查询条件表驱动（每条件单独 / 两两组合 / 空结果 / 已软删数据不出现）；汇总口径测试；截图；模拟机走查（选中结果数与导出条数一致）

### 批次四 · 资产与钱（P1）

#### M3-9 资产模块：账户停用 / 流水迁移 / 自定义分组

- 停用（`accounts.archived` 启用）：编辑账户页加「停用账户」开关；资产页把停用账户收进「已停用」段（默认折叠、行尾「已停用」标记）；记账的账户选择器不列停用账户（当前已选中的除外）；**净资产仍计入**（钱还在，只是不常用）
- 流水迁移（解 D026 的"有流水账户删不掉"）：编辑账户页加「把名下 N 笔流水转到…」（选择同账本账户）→ 确认弹窗写明条数与不可撤销 → 批量 UPDATE `accountId` + `updatedAt`；迁移完原账户可删（原删除拦截规则不变）

- 验收：停用账户不进选择器 / 净资产不变（DAO + Compose 测试）；迁移后两侧余额联动（DAO 测试：迁移 N 笔 → 原账户余额归零可删）；分组标题渲染测试；截图（资产页已停用段 / 编辑账户三处新入口）；模拟机走查

#### M3-10 理财快照与盈亏

- 数据：`asset_snapshots`（M3-0 已建）；`SnapshotDao`
- 口径（domain 纯函数 + 表驱动）：理财账户「总额」= 最近一次快照值（无快照则退回余额重算）；「盈亏」= 最近快照值 − 成本，成本 = 初始余额 + 净转入（转入 − 转出，含手续费按现有口径）
- 页面：资产页理财卡接真数据 → 点进「理财详情」：现值/成本/盈亏三数 + 快照列表（日期 + 值）+ 「记快照」（日期 + 金额 + 备注）+ 删除快照；走势小图先不做（自绘折线留 M6 打磨，避免与统计页图表口径打架）
- 明确不做：收益同步 / 自动抓取净值、多币种估值、理财产品的申购赎回流程
- 验收：盈亏纯函数表驱动（无快照 / 单快照 / 多快照 / 负盈亏）；`SnapshotDaoTest`；截图（理财详情 / 记快照）；模拟机走查

#### M3-11 分期房贷 + 信用卡年费

- 房贷计算器（domain `LoanMath`，纯函数 + 表驱动）：等额本息与等额本金——月供（首月/末月）、总利息、总还款、逐期计划（本金/利息/剩余）；与手算基准对账（含 0 利率、1 期、超长 360 期）
- 页面：我的 → 分期房贷——输入本金 / 年利率 / 期数 / 首期还款日 / 方式 → 结果卡 + 计划表（列表）→ 「按首期记一笔」（跳记一笔预填，分类由用户选；**不自动生成整个计划**——要循环请用周期记账）
- 信用卡年费（M3-0 已加列）：编辑信用卡账户时可填「年费金额 / 收费月 / 收费日」；资产页信用卡行副标题显示「年费 ¥480 · 每年 3 月 12 日」；到期未标记时行尾提示 → 点按 = 记一笔年费流水（分类「年费/手续费」）+ 标记 `lastFeePaidYear`（**不做后台通知**，只在打开资产页时判定）
- 验收：`LoanMathTest`（表驱动，两条公式各 ≥6 例）；年费到期纯函数（跨年 / 闰年 / 2 月 29 日 / 收费日 31 日）；截图（房贷计算器 / 资产页年费行）；模拟机走查

## 六、不做清单（M3 明确不做）

- **任何数量限制**（"免费 1 个 / 会员 3 个"的分支、升级引导、会员推广卡）——权益表里所有"数量限制类"在 penned 一律不做限制代码（方案 §三 B）
- 服务端相关：云同步、多人记账、账户/数据上报、统计埋点（M5 及以后）
- 后台任务：WorkManager / AlarmManager / 前台服务 / 定时通知（周期记账、年费提醒、愿望达成提醒都不引）
- 周期记账的**预生成策略**（一木式"创建时预生成未来 N 期、上限 1999 条"——已否，见 §五·3）
- 智能类（M4）：截图导入、OCR、一句话记账、自动记账（通知监听）、分类关键词规则、智能标签
- 系统集成（M5）：桌面小部件、悬浮球/悬浮窗、快捷磁贴、附件上传、WebDAV/局域网同步、全实体备份
- 打磨类（M6）：年总结报告、自定义小票模板编辑器、动效细化、图标的图标包/上传、统计里的一木式桑基图/报表表格/本月总结、一木的长按**批量编辑**（我们现有批量删除，批量改分类/账户进提案区）、日历的农历/节气/节日
- 技术侧：新增依赖、跨里程碑重构、改已冻结口径（applicationId / 版本号单一来源 / 更新协议 v1 / 零阴影扁平语言）
