# penned 开发工作流（全 agent 开发，防返工设计）

> 前提：本 App 由 AI agent 分会话完成，人类只做规格审批和里程碑验收。返工的最大来源不是"写得慢"，而是**会话之间失忆、规格含糊被自由发挥、验证缺失导致错误累积**。本工作流针对这三点设计。

## 一、返工的五个来源与对策

| 返工来源 | 对策 |
| --- | --- |
| 会话失忆：新会话不知道既有决策 | 仓库即记忆：AGENTS.md 入口 + docs 规格链，每个会话开工必读（写进工作流第一步） |
| 规格含糊 → agent 自由发挥 | 每个任务先有"验收标准"再有代码；规格冻结后才动手 |
| schema/契约中途变更 | schema v1 冻结 + Room migration 从第一天就强制；契约变更走决策日志 |
| UI 无验证 → 视觉债累积 | Roborazzi 截图测试入基线，里程碑做视觉验收（渲染 PNG 给视觉 agent 评审） |
| 大杂烩式集成 | 垂直切片 + 每个 slice 自带测试 + main 永远可构建 |

## 二、仓库记忆系统（M0 第一件事）

```
AGENTS.md                 ← agent 入口：项目是什么、硬性约定、开工必读清单、DoD
docs/
  可行性分析与技术方案.md   ← 已有：总方案、里程碑
  信息架构分析.md          ← 已有：页面结构
  local/                   ← 私密材料（真实账单/截图/反分析），已 gitignore 不入库
  一木记账权益.md          ← 已有：功能清单
  开发工作流.md            ← 本文件
  decisions.md             ← 决策日志：每条架构决策一行（为什么、何时定、是否可改）
  specs/                   ← 每个里程碑一份冻结规格（M0.md, M1.md…）
  plan/board.md            ← 任务看板：待办/进行/已完成 + 状态，会话之间传递进度的唯一真相
```

- **decisions.md 初始条目**（从既有分析沉淀）：金额存 Long 分；uuid 主键；软删 + updated_at + device_id；余额/统计一律重算不落库；账户外键可空；单 Activity + Compose；Room schema export 开启。
- **AGENTS.md 里写死"不许做"清单**：不引新依赖（升级是独立任务）、不跨里程碑重构、不加规格外功能（有想法记入 board 的"提案区"）、不改已冻结 schema（走 decisions 流程）。

## 三、依赖冻结（防"环境漂移"型返工）

- Gradle version catalog 固定：AGP / Kotlin / Compose BOM / Room / 协程版本，**锁定具体版本号**。
- agent 默认**不升级任何依赖**；需要新库（如 Vico、ML Kit）→ 先写进 board 提案，人批准后加入 catalog，并记入 decisions。
- 用 Room 的 schema export（JSON 进版本库）+ Migration Test，任何 schema 变更必须带 migration，否则测试红。

## 四、开发回路：每个里程碑五段

### A. 冻结规格（半天，人审批）
产出 `docs/specs/M{n}.md`：本里程碑实体/页面/行为清单 + 每条验收标准 + 明确的"不做"清单。已有文档（IA/反分析）是输入，规格只是把范围切出来。**规格一经批准即冻结**，变更进下一里程碑或走 decisions。

### B. 走通骨架（1 个会话）
最先建"最薄的端到端"：工程可构建 → 一个页面显示 → 一次 DB 写入读出 → 一条测试跑过 → 打出一个可安装 APK。骨架先行意味着后续所有任务都在"已能构建、已能验证"的地面上干活，集成问题第一天暴露。

### C. 任务切片循环（主体，每个任务一个会话）
- 切片规则：**垂直切片**（数据层→UI→测试一条龙）优于水平分层（先写完所有 DAO 再写所有 UI——agent 模式下后者会产生大量无人验证的代码）；单任务一个会话内可完成并验证。
- 每个任务在 board 上的模板：
  ```
  ## T{n}：{标题}（里程碑，状态）
  规格来源：specs/M1.md#x.x
  验收标准：1) … 2) … 3) 测试清单
  依赖：T{n-1}
  输出：commit 列表 / 新增测试数 / 遗留问题
  ```
- 会话开场白固定为：读 AGENTS.md → 读 specs/M{n}.md → 读 board.md 找下一个就绪任务 → 干活 → 更新 board。**这个循环本身就是工作流的核心。**

### D. 集成 + 视觉验收（里程碑末）
- 全量 `./gradlew build test lint` 必须绿。
- UI 门：Roborazzi 截图测试渲染各页面 PNG → 视觉 agent 逐页评审（布局/可读性/一致性）→ 修完再入基线。人只看最终 PNG 集。
- 数据门：导入器用真实一木文件做金样本（脱敏 fixture 提交进仓库，751 行断言逐列比对）。

### E. 发布切版（半天）
versionCode+1（构建脚本生成，禁手改）→ changelog → tag → 构建签名 APK → 生成 update.json（sha256/size/urls）→ 传静态托管 → 旧版本走应用内更新验证一遍闭环。

## 五、验证门（Definition of Done，写进 AGENTS.md）

一个任务只有满足以下全部才算完成：
1. `./gradlew build test lint` 全绿（Windows 本地跑，Git Bash）
2. 涉及 DB：附 migration 测试；schema JSON 已更新
3. 涉及 UI：附 Roborazzi 截图测试，Preview 可渲染
4. 涉及钱/日期/解析：附单元测试（金额全用 Long 分断言；日期解析用表驱动用例）
5. board.md 已更新（状态、输出、遗留问题）
6. 提交信息 = 任务号 + 一句话；小步提交

测试分层（ROI 从高到低）：纯 Kotlin 单测（金额/日期词解析/规则引擎/一句话 NLU——无 Android 依赖，最快最稳）→ DAO 测试（Robolectric）→ ViewModel 测试 → 关键流程 Compose 测试（记账到入库一条）→ 截图基线。**禁止只有 UI 没有单测的 slice 合入。**

## 六、何时用多 agent 并行

主干代码（相互依赖的页面/数据层）**单线程推进**——并行改同一仓库是 agent 项目返工重灾区。适合 fan-out 并行的是**规格冻结后的独立批量任务**：
- 截图导入的版式规则模板（N 个来源 × 独立编写/独立测试）
- 分类关键词初始规则表、图标资源生产
- 批量补测试、批量文案

这类任务先在 board 里拆成互不依赖的条目，再用动态工作流/多会话并行派发，产出统一回到 main。

## 七、反模式清单（每个会话开工读一遍）

1. 不读 docs 就动手
2. 规格外"顺手加功能"
3. 无测试的 slice 声明完成
4. schema 变更不写 migration
5. 依赖擅自升级
6. 跨里程碑大重构（想重构 → board 提案，人裁决）
7. 用 Double 存钱（立即打回）
8. 会话结束不更新 board（下个会话必然返工）

## 八、套到当前计划

M0 开工日 = 一次会话完成：工程骨架 + version catalog 冻结 + AGENTS.md/decisions.md/board.md 建立 + schema v1（按已定稿结论）+ migration 机制 + Roborazzi 跑通。M0 规格冻结后，后续每个里程碑按 A→E 循环推进。
