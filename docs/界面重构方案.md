# 界面重构方案（M1 后置重构）

> 背景：M1 功能面已收尾，但界面上限被三件事压住——主题层是 M3 默认值、分类色是哈希算出来的彩虹、inset 算了两遍导致顶部死带。
> 本文是这轮重构的**视觉与交互规范**，代码里的 token 以本文为准；改规范先改本文。
> 决策依据：D024（UI 规范）、D025（inset 约定）取代 D019 的"分类图标 = 哈希色块"。

## 一、诊断（重构前）

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | 分类色是彩虹：同屏出现蓝/紫/洋红头像，统计页环形图与占比条是紫/洋红/橙 | `ui/home/HomeScreen.kt:411` `categoryColor()` 用黄金角把名字哈希成任意色相 |
| 2 | 没有设计层：`Typography()` 全默认、无 Shapes、无间距常量，圆角在 8 处硬编码（16/14/12/10/8dp） | `ui/theme/Type.kt:5`；各屏 `RoundedCornerShape(...)` 字面量 |
| 3 | 卡片与背景只差 ~2% 亮度，无边界、无层次 | `BackgroundLight F8FAF9` / `SurfaceLight FDFEFE` / `SurfaceContainerLight F0F3F2` |
| 4 | 品牌色当正文色用，对比度不足（3.3:1） | 首页"搜索"、搜索页"清除"直接用 `primary = #2F9E8F` |
| 5 | M3 `error` 槽位是默认紫，与青绿身份冲突 | 锁屏键盘 `LockScreen.kt:74` |
| 6 | 深色下冷启动闪白 | `res/values/themes.xml` 仅浅色、无 `values-night` |
| 7 | **顶部死带：状态栏 inset 算了两遍** | `PennedApp.kt:58` 外层 Scaffold 把状态栏 inset 作为普通 `padding` 给 NavHost（普通 padding 不标记 inset 已消费），内层 `SearchScreen.kt:122` 的 Scaffold + TopAppBar 再加一遍 → 真机上 2× 状态栏高度的无内容区。同型问题：9 个下钻页 + `MineScreen`/`AssetsScreen` 内层 Scaffold（底部导航栏 inset 同理重复） |
| 8 | 交互陈旧：8 处 `AlertDialog` 二次确认、列表零手势、页面硬切无转场、返回键是文字 `"‹ 返回"`、FAB 是文本 `"+"`、勾选是 `"✓"`、箭头是 `"›"` | 全仓 grep |
| 9 | 删除不可撤销；记一笔顶栏「编辑」是 disabled 死 UI | `board.md` 待办 |

## 二、设计原则（五条，评审按这个判）

1. **金额是主角**：每屏最大的字一定是金额；数字一律等宽（`tnum`）、右对齐成列。
2. **一张表面语言**：白卡 + 1dp 发丝线 + 16dp 圆角，全局不用阴影；深色靠表面提亮表达层级。
3. **颜色只表达信息**：界面唯一饱和色是支出红/收入绿；分类颜料只出现在分类头像、图表、占比条，绝不用于装饰。
4. **位置感一致**：Tab 页 = 可滚走的页头（无固定 app bar）；下钻页 = 紧凑顶栏（真返回箭头 + 标题 + 动作槽）。
5. **动效回答动作**：转场/抽屉/列表增删/滑动，每种都对应一个用户动作，不做装饰动画；系统"动画时长缩放 = 0"时全部关闭。

## 七、交互范式

1. **底部抽屉代替弹窗**：账户选择、预算分类选择、更多操作 → `ModalBottomSheet`（从底部升起、可下拉关闭）；纯文本输入（改金额、命名）保留居中弹窗。
2. **行左滑删除 = 二次确认 + 撤销**：左滑越过阈值先弹确认（标题写清删的是什么，如「删除这条流水？」+ 分类与金额；账户行是「删除「微信」？」+ 余额），确认后才软删 → 底部 Snackbar「撤销」（10s）。**只滑一下就删太容易误伤**（用户实测反馈），撤销是事后补救、不能替代事前确认；长按多选模式保留不变。
3. **转场与列表动效**：下钻页共享轴滑动淡入、Tab 切换淡入淡出、列表增删 `animateItem()`、子分类条带展开 `AnimatedVisibility`；读系统动画缩放，为 0 时全部关闭。
4. **触感反馈**：键盘按键、长按进多选、左滑越过删除阈值。

## 八、导航与 insets（D025）

- Tab 页（首页/日历/资产/统计/我的）：无固定 app bar，页头是列表首项，随内容滚走。
- 下钻页：`PennedTopBar`（返回箭头 + 标题 + 动作槽）。
- inset：外层 `Scaffold` 的 padding 交给 `NavHost` 时用 `Modifier.padding(padding).consumeWindowInsets(padding)` 标记消费，内层 `Scaffold`/`TopAppBar` 不再重复加状态栏与导航栏高度。
- 深色：新增 `values-night/themes.xml`，冷启动窗口背景与 Compose 主题一致。

## 十一、实施结果（2026-10-06）

九个切片已全部落地并提交（UI-0 文档 → UI-1 token → UI-2 组件库+图标+inset → UI-3 首页+搜索 → UI-4 记一笔 → UI-5 统计+资产+详情 → UI-6 其余 7 屏 → UI-7 转场动效 → UI-8 模拟机验证），详细清单见 `docs/plan/board.md` 的"界面重构"条。

实施中与本文有出入、以代码为准的三处：

1. 环形图端头用 `Butt` 而不是圆头——圆头半径约 11°，会在 3° 缝隙上互相盖住；
2. 分类头像的淡底透明度定为 16%（浅）/ 30%（深）——14% 在浅色下偏弱、深色下八色会糊成灰；
3. 「不报销」chip 保留但改为禁用样式（只读表达"新记为不报销"，可编辑留 M3），没有做成可点入口。

顺手修掉的三个真 bug（都不在本方案范围内，是实施时被测试与模拟机抓出来的）：撤销后行被"复活的滑动状态"再删一次、金额语义色读的是系统深色而非主题入参、添加账户预设 chip 覆盖已输入名称。

## 十二、账户管理（2026-10-06 第二轮，2026-10-07 按参考图重做）

**背景**：M1 的资产页只能加账户，账户条目本身没有任何删除入口（点不了、长按无反应、不能滑），误加只能靠删整个账本；新增账户是一张居中弹窗——8 个预设竖排 chip + 两个白框输入，一行一个控件没有版面结构，而且因"弹窗内文本输入在 Robolectric 不 idle"连截图测试都做不了（只能断言入口存在）。

第二轮先补了删除链路（AC-1~AC-4）；用户随后给出三张参考图要求按图重做，本节的版面描述以 **2026-10-07 的 AD-1~AD-6** 为准。参考图只借结构与信息层级，**不抄**品牌图标（微信/支付宝/京东/QQ）、植物插画与一木的绿色：账户头像仍是我们的颜料首字圆，品牌色仍是青绿。

### 添加账户类型抽屉（对标参考图 2）

四个大类**一次铺开**（此前是"分段 tab + 单组网格"两段式），每组标题 + **5 列图标格**，每组末尾一个「自定义」格：

```

信贷账户   ⬤信用卡 ⬤花呗 ⬤自定义
投资理财   ⬤理财账户 ⬤自定义
负债       ⬤欠款 ⬤自定义
```

### 金额千分位（AD-1）

`Money.format(cents, grouped = true)` 默认输出 `3,500.00`（全 App 一致，大额更好扫读）；**输入框回填一律 `grouped = false`**——光标与 `parseToCents` 都不吃逗号（`AddViewModel` 编辑回填、预算金额、账户表单三处）。CSV 导出走原始分，不受影响。

### 删除语义（D026）

软删、可撤销；**名下有流水则拒绝**——删了流水外键会悬空，净资产凭空少掉这笔钱，而流水还留在列表和统计里，两端口径对不上。空账户（含一木导入按名创建的账户）照常可删。

### 生效账本与备注（D027 / D028）

- **生效账本**：点开是「全部账本」开关 + 逐账本勾选（**所属**账本恒定可见、置灰带标记）。行摘要显示「全部账本」或列出生效的账本名（如「日常账本、test」）。新建账户默认只勾所属账本，与老行为一致。
- **余额是钱包口径**：恒等于「初始余额 + 该账户名下全部流水」，**与可见账本无关**——同一个钱包在哪个账本看都是这个数，勾掉一个账本不会让余额变。
- 删账本不动"生效账本为全部账本"的共享账户（否则那边账本的流水外键会悬空），但会级联清掉指向它的勾选引用。
- **备注**：只作个人备忘，不参与任何计算，资产页行副标题显示。
