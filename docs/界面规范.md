> **本文是全 App 视觉与交互的唯一出处**：token 值、组件契约、逐屏版式、无障碍规则都在这里；代码与本文不一致时，先改本文再改代码。
> AR 轮（2026-10-08）动机：用户反馈「界面风格老旧、像老式工具软件，现代化美感不足」。AR 轮把**视觉层整个重做**（token / 组件 / 版式 / 动效 / 无障碍），**业务层一行不动**（Room/DAO/domain/ViewModel 口径/路由/字段）。
> 本文**取代** `docs/界面重构方案.md` 第一~八节与该文档的 token 表述（那份文档保留作历史记录：UI/AI/AF…AQ 各轮的决策过程仍在里面）。

> **配色经过五轮**：AR 换盘（D043）→ RA 降噪降饱和（D045）→ v3 实心亮块（D046）→ v4/v5 一个色相三种强度（D047/D048）→ v6 图标底统一淡灰绿（AS 轮，见 §4）。

## 二、设计原则（五条，评审按这个判）

1. **金额是主角**：每屏最大的字一定是金额；数字一律等宽（`tnum`）、右对齐成列；金额字重 700，压过一切标签。
2. **扁平分层，不描边、不投影**：页面底（`background` 中性灰）→ 卡片（`surface` 纯白，16dp 圆角，**无边框**）→ 浮层（FAB/悬浮入口/提示条/抽屉，靠填充色或发丝线与卡面分开）。发丝线只用于**卡片内的行分隔**。**全局零阴影**（沿用 D024，只是把"描边"也去掉了）。
3. **颜色只表达信息**：界面唯一饱和色是支出红/收入青绿；品牌青绿只用于"可操作/已选中/进度"；分类颜料只出现在**图表、占比条与宫格小圆点**，绝不用于装饰（AS 轮起圆形头像不再吃颜料——统一淡灰绿）。
4. **位置感一致**：Tab 页 = 无页头大标题（Tab 栏已表达身份，D035/AR 轮推广到全部 Tab 页）、内容直接进首屏；下钻页 = 紧凑顶栏（返回箭头 + 标题 + 动作槽）。
5. **动效回答动作**：每种动效对应一个用户动作，时长走四档 token（120/180/220/300ms），不做装饰动画；系统"动画时长缩放 = 0"时全部关闭。

**七条硬规则**

1. 填充上的文字用 `onPrimary`，容器上的文字用 `onPrimaryContainer`——**不要**把 `primaryInk` 写在 `primaryContainer` 上（浅色下只有 4.46:1，差一点）。
2. 品牌色**永远不当作正文色**直接写在白/灰底上（旧口径 primary 只有 3.3:1）；要写就用 `primaryInk`。
3. 日头条右侧的「收 X 支 Y」用 `onSurfaceVariant`（RA 轮起底色是极淡青灰，不再靠 alpha 弱化；旧版在青绿底上用 `onPrimaryContainer` @85% 是当时的口径）。
4. 阴影 token 全 `0.dp`：不引 `Modifier.shadow`，M3 组件的默认 elevation（FAB 6dp、Snackbar 6dp、NavigationBar 3dp tonal）一律显式归零。
5. 进度条/环/柱等"图形"用 `primary`（不是更亮的青）——`#14B8A6` 那一档在白底只有 2.49:1，达不到 1.4.11 的 3:1，已从 token 里删除。
6. 深色模式不用纯黑，靠"表面提亮"表达层级：`background #0F1113` → `surface #181A1D` → `surfaceContainer #212429` → `surfaceContainerHigh #282C31`。
7. 冷启动窗口背景跟着主题走：`values/themes.xml` = `#F4F5F7`、`values-night/themes.xml` = `#0F1113`（消白闪，D024）。
8. **大面积一律极淡，色相只在小面积上给满**（v4 D047 / D048，v6 AS 轮再收一档）：横跨整屏、每天重复的色带（日头条）彩度 ≤8%；**图标底 = 统一淡灰绿 12%/22%**（与白卡 1.17:1，跟日头条底同一档，**不再分槽**）、**图表细件 = 色相 45%/65%**——两者都是"纸"不是"色块"，识别靠墨色字形（图标底）与旁边的数字（细件）。色相给满只留在**小面积**：3dp 竖条、宫格选中态实心、宫格子分类小圆点。

## 四、分类颜料盘 v6

**五轮的结论（先看这个）**：AR「高彩度深色 ink + 12% 淡底」→ 用户说**太艳、太明亮**；RA「压彩度 ≤50% 并加深」→ **绕回了国画色**（深、灰、土）；v3「实心亮档块 + 深档字」→ **"又艳起来了，与整体不协调"**；v4/v5 把"面"压到 12% 淡底、色相只给细件与状态 → 用户仍点名「**所有分类图标改为淡灰绿色。进度条/占比图颜色不改**」（附首页行与支出数据两张截图）。四次失败都栽在同一处：**图标底在承载分类身份**。而用户点名的样板始终是首页**日头条那一栏**——极淡的青灰底 + 3dp 深青竖条 + 墨色日期。于是总口径再收一档：

> **大面积一律极淡；色相只在小面积上给满。**
> **v6 追加：图标底连"分槽"也取消——全 App 一个淡灰绿，色相只留给图表细件与小圆点。**

每槽只剩**一个色相**（[hue]），按三种强度用——**不再有"亮档/中档/深档"三份颜色**：

| 强度 | 用在哪 | 口径与实测 |
| --- | --- | --- |
| **图标底 12%（浅）/ 22%（深）** | 分类头像、宫格气泡、账户/账本/导入行图标——**全 App 一个色** | 淡灰绿 `iconHue`（`#0D8557` / 深 `#7AEBC0`）：浅色叠白卡 `#E2F0EB`、与白卡 **1.17:1**，跟日头条底（1.12:1）同一档；深色叠 `#181A1D` ≈ `#2E4841`、1.75:1。**不按 3:1 守**（装饰性块，识别靠上面的墨色字形 + 旁边的名称），只留一条 `groundVisible` = **1.10:1**（"不许比日头条底还淡"，见 §11.1）。 |
| **细件 45%（浅）/ 65%（深）** | 占比环、图例点、占比条——**分类色只剩这里** | 比图标底浓、比状态淡的那一档（用户第二轮点名「支出占比的配色也需要改动」，而环是页面上最大的一块颜色）。45% 是渲染比出来的线：≥45% 时 4dp 的占比条还看得见，≤25% 就真看不见了（`build/chart_pale.py` 按真机尺寸比过 12/25/40/55/74/100% 六档）。**代价写清楚**：与卡片 **1.84~2.00:1**、与浅轨道 **1.52~1.72:1**，够不上 3:1——环/条只是辅助视觉，占比数字与金额每一行都写着（§11.1 的 `markVisible` 就是守这条线）。 |
| **全强度 100%** | 宫格"有子分类"9dp 小圆点（分类色）、宫格选中态（品牌青绿 `primaryInk` 实心 + 反白） | 日头条那根 3dp 竖条的角色：小面积、给满。八槽按**对比度**对齐（D047 时它们还兼任"选中态实心"，解到"白字压上去 = **4.5:1**"，所以明度随色相走：玫红/紫/靛到 L50~60、翠/金压到 L29~34——绿、金的物理亮度高，压到同一明度白字就糊了）；AS 轮起这一档只剩"小圆点的源色"一个角色，**值一个都不动**（细件是从它们稀释出来的）。 |

**图标底上的字形不染颜料**，用 `onSurface` 墨色（浅色 15.6:1、深色 8.2:1）——与日头条的墨色日期同一口径。前几轮把字形染成彩色，正是"艳"与"国画"两种观感的直接来源。

**图标底不分槽**：全 App 一个淡灰绿 `iconHue`——与 2 号翠槽同值，但**独立成 token**（改分类色不动图标底，反之亦然）。账户类型色（信用卡玫红/现金橙/储蓄卡紫/理财青）在 AS 轮一并退场：类型写在名字旁（「招商银行 · 信用卡」），不再靠图标颜色表达。

**12% 是那条线（诚实记录）**：日头条底约等于品牌青绿 8% 淡底。v4 时 12% 是"与日头条同一档偏淡、又还能分清八个色相"的折中；v6 图标底不再分槽，这条线只剩前半句——**与日头条底同档的"纸"**：再淡（≤6%）圆就与白卡糊成一片（`groundVisible` = 1.10:1 守着），再浓就又回到"色块"。

**分配规则（沿 D024/D040，未变）**：名字 → 稳定哈希落槽（同名同色、跨页稳定）；同一张图里出现的一组分类走 `assignSlots`（**不撞色就不动**，撞色才穷举 P(8,k) 搜"最小色相差最大"者），目标 `MIN_HUE_GAP = 45°`。

**这套盘的极限（诚实记录，未变）**：色相 341/17/157/193/267/233/295/40，**最多能挑出 5 个两两 ≥45° 的颜色**（旧盘同样是 5 个的极限，见 D040）；一屏 6 个彩色分类时最小色相差退到 **36°**（这是**最优解**，`assignSlots` 会穷举确认），靠"淡底色 + 分类名 + 占比数字"一起区分。

> **槽位顺序不是色相顺序**（341/17/157/193/267/233/295/40）。哈希落槽决定了"哪几个真实分类会同屏"，
> 所以槽位与色相要**错开配**：AR 轮实测发现按色相顺序排会让「晚餐」与「工资」（真机上最常用的两个分类）
> 只差 28°（旧盘是 46°），一眼就能看出"两个都是紫的"；按上表错开配之后，
> 真实数据会同屏的槽位两两 **≥46°**。改色相表时记得重算这一条。

## 六、间距 / 圆角 / 图标

**间距**（`PennedSpacing`）：`xs 4 / sm 8 / md 12 / lg 16 / xl 20 / xxl 24 / huge 32`。
- **屏边距恒 16dp**（首页悬浮入口的 368dp 形变与既有测试盯着它，不要改）；
- 卡片内边距 16（紧凑块 12）、卡间距 12、分组间距 24（沿用）。

| `extraSmall` | 8dp | 徽标、进度条端头 |
| `small` | 12dp | 键面、输入框、内块、按钮 |
| `medium` | 16dp | **卡片**（含分段卡） |

## 十、交互与状态完整性

**六态审查表**（逐屏过：载入 / 空 / 有数据 / 禁用 / 选中 / 错误）：

- 载入：只对"真的会等待"的地方做（详情页载入、统计切换期）；其余页面 Room 响应式、无 loading 态，不要为好看加假骨架。
- 空态：一律给"出路动作"（记账/去设置预算/去添加账户），不给死文案。
- 禁用：给**原因文案**（如账户页「该账户下有 3 笔流水」），不做"点了才说不能"的死按钮（D026）。
- 成功反馈：保存/删除/导入完成后给轻触感 + 提示条（本轮补上"保存成功"缺的那一环）。
- 撤销：首页与资产页的单条左滑删除（点动作区的「删除」直接软删）、批量删除一律 Snackbar 撤销 10s（D031/D026）——**二次确认弹窗两处都已退场**（"必须滑开再点按钮"取代它，D053/D054）。（资产页账户删除另有一条既有护栏：名下有流水则拒绝并提示条数，D026。）
- 选中：多选模式的行、选中的 chip/分段/月格，除颜色外必须有**形状或字重**差异（不靠颜色单一信号）。

**按压反馈**：卡片/行 → `PennedPressable`（按压底色 120ms，不缩放：整行缩放会显得在抖）；键面 → 底色变化 + 触感（`AmountKeyboard`/`PinKey` 各自实现，口径一致）；按钮/chip → ripple + 触感。触感点：键盘键、长按进多选、左滑动作区定格展开（`SwipeActionRow`，UI-12 起；旧口径是"左滑过阈值"）。

## 十一、无障碍（WCAG 2.1 AA 基线）

1. **所有文字 ≥4.5:1**（表见 §3 与 §4 的实测列），大字与非文字控件 ≥3:1；`ContrastTest` 把 **103 对**配对写成表（图标底 4 对 + 宫格选中态 2 对 + 颜料细件 × 八槽与中性 + 宫格小圆点 × 八槽与中性、深色全套、提示条反向层、日头条三对，UI-12 另加左滑动作区 4 对：`onSurface/surfaceContainerHigh` 与 `onError/error` 浅深各一），改色值立刻红。**两条淡档是明确的例外**：①**图标底**（装饰性块，识别靠墨色字形 + 旁边名称）不按 3:1 守，只留 `groundVisible` = **1.10:1**（与日头条底 1.12:1 同档，"改淡过头立刻红"）；②图表细件按 `markVisible` = **1.40:1（浅）/ 2.30:1（深）** 守——这不是把 3:1 放宽，而是用户点名要「占比也偏淡」之后、物理上到不了 3:1（实测 1.84~2.00:1）的诚实记录，外加一条"改淡过头立刻红"的线（≤25% 时 4dp 的占比条就真看不见了）。两条理由都写在 §4。
2. `outline` 是**装饰性**边界（1.43:1），按 1.4.11 不承担识别职责：承担识别职责的箭头/图标一律 `iconMuted`（3.30:1）。
3. **触控目标**：图标按钮与设置行 = **48dp**（`PennedDimens.iconButton`）；chip 32dp、分段 36dp（轨道 +3dp 内边距 = 42dp 可点）——按 **WCAG 2.5.8（AA，≥24dp）**核过，没有一律撑到 48dp 是因为记账页的 chip 流与键盘密度会崩（48dp 的 chip 一行放不下三个）；chip 之间留 4~8dp 间距降低误触。
4. **字号最小 12sp**（`labelSmall` 11→12），不使用 11sp 以下字号。
5. **字体缩放**：`FontScaleTest` 在 `fontScale 1.5 / 2.0` 下渲染首页与记一笔（图落 `fontscale_*.png` 供逐张过目）。据此做了两处自适应：`PennedStatCells` 在 ≥1.3× 时从"三列"换成"标签左 + 数值右"的竖排（否则金额被截成 `1,500.…`）；记一笔的 chip 行改 `FlowRow`（否则最后一个 chip 被挤成竖排单字）。
6. `contentDescription` 审计：所有纯图标控件有描述（「返回」「搜索」「隐藏金额」「重命名」「删除」…），装饰性图标为 `null`；账本页行内动作已从文字按钮改图标按钮，断言随之改 `contentDescription`（仓库既有约定）。
7. `SwipeActionRow` 的每个动作都进 `customActions`（首页行「编辑 + 删除」、资产页账户行「删除」）——左滑对读屏用户完全不可见（D044；UI-12 把首页那处从一个动作扩成两个，UI-13 起资产页也走同一组件、动作列表自动一致）。
8. 颜色不作唯一信号：金额带 +/- 符号、图表有图例文字、选中态带形状/字重差（分段控件的选中段比未选段重一档字重，底栏选中图标放大 1.08×）。
9. 深色模式与浅色同等对待：所有新配对都进 `ContrastTest`，深色基线逐张过目。

## 十二、工程约定（不变量与护栏）

1. **token 是唯一出处**：`TokenLiteralGuardTest` 扫 `ui/` 源码把关，规则两条——① `Color(0x…)` 只允许出现在 `ui/theme/`；② `padding/PaddingValues/size/width/height/heightIn/spacedBy/RoundedCornerShape/offset` 这些调用里**不允许就地写 >4dp 的字面量**（0~4dp 是发丝线/微调这类无意义值）。具名常量（如 `private val ChartHeight = 96.dp`）与确有必要的就地值（加 `token-ok` 注释说明）放行；`ui/theme/` 内部不受限。AR 轮据此把 34 处就地值收进 `PennedDimens`。
2. **文案与格式化一律不动**：`Money.format`、`HomeGroups`（`今天 10月6日 周二` / `2026/10` / `15:59`）、`AddDate`、`StatsPeriod/StatsStrip/StatsTrend/StatsMath` 的输出串是纯单测的护栏，本轮一个字符不改。唯一例外：用户已裁的"去掉资产/日历重复页头"。
3. **几何不变量**：悬浮入口 368↔56dp、`MotionSpec.PAGE = 300ms` 且 `== BAR`、`PARALLAX = 3`（≥2 否则滑动中露底）、`AddEntryMotion.LABEL_FADE`——形变与转场测试盯着这些数，改手感先改 `MotionSpec` 并同步测试。
4. **inset（D025）**：外层 `Scaffold` 的 padding 给 `NavHost` 时用 `Modifier.padding(padding).consumeWindowInsets(padding)`；新下钻页一律 `PennedTopBar`。
5. **每个目的地不透明（D041）**：Tab 根与下钻页根都必须自铺 `background`，pop 时父页画在子页之上。
6. **业务层零改动**：Room schema/DAO/repository/domain/ViewModel 口径/路由/字段一律不动；UI 需要新状态时只加"纯 UI 状态"。
7. 依赖不新增（AGENTS.md）：不引字体文件、不引图表库、不引图标库。
8. `Roborazzi` 基线不入库（在 `app/build/` 下），每次 `./gradlew test` 自动重录；**"逐张过目"是唯一视觉门**，但关键几何/像素另有断言（D042a 的预算条像素回归、形变几何、转场中途位置）。

## 十三、实测（2026-10-08，AR 轮收尾）

## 十三·补七、记一笔顶栏返回闪退修复（UI-11，2026-10-09）

- **用户报 bug**：记一笔页面点左上角返回 → App 直接退出（系统返回则正常回首页）。
- **根因（两处叠加）**：①`PennedApp` 读首页 flash 用的是 `getStateFlow(HOME_FLASH_KEY, null)`——**裸 `null` 让泛型推成 `Nothing?`（JVM `Void`）**，读取处被插 `checkcast java/lang/Void`，真读到 `"已记账"`（String）就 `ClassCastException` 闪退；②`AddTransactionScreen` 的 `onBack` 错接成 `onDone`——"返回"走"保存完成"的流程（写 flash + pop），于是顶栏返回必崩、系统返回（只 pop、不写 flash）正常。本次崩溃与"保存完成"同源：日志里用户保存那笔 6.00 元与 46ms 后的崩溃同秒。
- **定案（D052）**：①**类型显式化**——`getStateFlow<String?>(…)`、`mutableStateOf<String?>(…)`、`set<String?>(…)`、变量标 `String?`（别让 `null` 参与泛型推断）；②`AddTransactionScreen` 拆出 `onBack`（只 `popBackStack()`），`onDone` 只留给保存完成——"返回"不再弹假的「已记账」。

## 十三·补八、首页流水行改 QQ 式左滑动作区（UI-12，2026-10-10）

- **用户报缺陷**：「首页账单条目**极易误触**向左滑动删除条目」，要求对齐移动端 QQ：左滑依次露出两个按钮、**完全展示后不可再移动**、**松手后按钮不消失**、此时可点按钮 —— 按钮定为「编辑」「删除」。

## 十三·补十二、退款 / 优惠录入（M3-2，2026-10-12）

**问题**：M1 起 `refundCents`/`discountCents` 只是导入数据的只读展示，手动记账记不出"退了多少钱"；首页对全额退款的流水显示 `-0.00`，看不出为什么是 0。

**口径**（D069/D075）：落库的 `amountCents` 恒为**净额**（原价 − 退款 − 优惠，下限 0），退款/优惠各存原值；编辑时金额框反推回原价，往返幂等。余额与统计仍只读 `amountCents`——一行口径没改。

**记一笔**
- 信息条（支出/收入）在「标签」之后新增两个 chip，自绘图标：**退款 = 指向左的回退箭头**、**优惠 = 百分号**；空态是默认 chip 样式，填了值就转选中态并带上数值（`退款 30`），与「手续费」同一范式
- 点 chip = **把金额键盘指到那一格**（同一个键盘、同一套表达式/⌫/C），不弹二次输入框；键盘上方出现提示条：左「正在输入：退款」、右当前值、末尾「回到金额」——主金额始终留在信息条右上，不被顶掉
- 键位在退款/优惠格时，右下动作键仍是「完成」（保存整笔），"金额"格有待求值算式时才显示 "="
- 信息条下方（有退款或优惠时）加一行算式：`实付 70.00（100.00 − 退款 30.00 − 优惠 5.00）`，`bodySmall` + `onSurfaceVariant`，不占位置时不渲染
- 「再记」清空金额/备注/退款/优惠，键盘回到主金额

**首页流水行**
- 时间行右侧一个 `PennedBadge`：`全额退款`（净额 0 且退过款）/ `退款` / `优惠`——**一行只挂一个**，退款优先
- `MoneyText` 净额为 0 时**不写符号**：支出全额退款行显示 `0.00` 而不是 `-0.00`（说明责任交给标记）

**详情页**
- 「退款」「优惠」两行由只读改为**可点**（整行可点 + 尾部 `ChevronRight`，与 `PennedListRow` 同语义），点进编辑页；其余明细行保持只读
- 「已全额退款 / 部分退款」徽标判定改走 `RefundMath.isFullyRefunded`（与落库同一处口径）
